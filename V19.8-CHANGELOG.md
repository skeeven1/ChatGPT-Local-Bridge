# ChatGPT Local Bridge V19.8

## Runtime et démarrage

- Une seule autorité de version (`bridge-version.mjs`) alimente le bridge, le runtime et OpenAPI.
- Le chargeur ESM convertit systématiquement les chemins Windows avec `pathToFileURL()`.
- Le serveur HTTP et le lanceur refusent de démarrer si le runtime, le verrou et la version du bridge divergent.
- `npm run test:runtime` produit les trois jalons attendus : `Agent Runtime loaded`, `Version compatible`, `Bridge ready`.

## Perception et fenêtres

- Ajout de `window-intelligence/` avec `WindowContext` complet : HWND, PID, processus, titre, bounds fenêtre/client, visibilité, état réduit/maximisé/actif, focus, moniteur et DPI.
- Ajout de la lecture Win32 réelle dans `ui-helper.ps1`.
- Ajout de l'inspection de l'arbre Windows UI Automation.
- Ajout de `ui-intelligence/` et d'une détection Paint privilégiant UI Automation, puis les informations système et enfin la vision.
- Ajout de `perception-fusion/` avec scoring multi-source et refus sous le seuil de confiance.

## Action, validation et recovery

- Ajout du modèle d'action V19.8 séparant commande envoyée, exécution, changement observé et objectif atteint.
- Chaque réponse GPT Actions contient maintenant un `actionModel`; une commande GUI non vérifiable n'est pas marquée comme objectif atteint.
- Ajout du validator avant/après pour état fenêtre, UI, différence visuelle et résultat attendu.
- Ajout du Recovery Manager : retry, recalibrate, refocus, rediscoverWindow et abortSafely.
- Les jobs raster recalibrent leurs coordonnées si Paint est déplacé ou redimensionné pendant le dessin.

## Compatibilité et sécurité

- Les 14 routes macros et 49 sous-actions existantes sont conservées.
- Le protocole historique `chatgpt-local-bridge-v15` reste inchangé pour la compatibilité du transport.
- Le confinement des chemins, les limites de taille, les listes d'exécutables bloqués, les confirmations Windows et le rejet des SVG actifs restent en place.
- Aucune primitive de shell distant arbitraire n'a été ajoutée.
